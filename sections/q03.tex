\begin{frame}{Q3 — Prefix caching과 prefill 버킷 설계}
  \small
  \hd{The effect}
  \begin{itemize}
    \item Without prefix caching, prefill buckets are sized to the full prompt length.
    \item With a cache hit, the tokens actually computed
          $= R = (\text{prompt length}) - (\text{cached prefix})$. $R$ varies per request, usually small.
    \item Pick the bucket from $R$, not the prompt length — a prompt-sized graph pads away the benefit.
  \end{itemize}

  \hd{Approach}
  \begin{itemize}
    \item Look up the cache $\to$ compute $R$ $\to$ smallest compiled bucket $\ge R$.
    \item One chunk-sized prefill graph $+$ a few small tail buckets; long residuals repeat the chunk graph.
    \item Bucket sizes from the real post-cache residual-length distribution, recompiled offline.
    \item vllm-rbln does this: one prefill graph at the chunk size; prefix reuse at a finer sub-block
          granularity; matched KV copied into the request's blocks before the forward.
  \end{itemize}
\end{frame}
